# v6.3 Vertical Market Selection：垂直证书市场选择

## 1. 核心纠偏

前一版把证书方向说成泛泛的 AI Office / Agent Operator，仍然太抽象。

正确方向应该是：

```text
不要先做横向通用证书。
要先选一个具体垂直领域。
在该领域内，把 AI / Agent / Crypto Proof 作为能力加速层和可信证明层。
```

也就是说：

```text
Vertical Domain Certificate
+
AI / Agent Augmentation
+
Crypto Native Proof
+
Verifier Portal
```

## 2. 为什么必须垂直化

横向 AI 能力的问题：

```text
太抽象，不知道谁必须买。
太泛泛，难形成可信证书标准。
太容易被免费教程和工具功能替代。
很难让用人单位相信证书价值。
```

垂直证书的优势：

```text
有明确岗位。
有明确能力要求。
有明确考试题和项目任务。
有明确 Verifier。
有明确付费方。
证书更容易被招聘、晋升、接单、录取或客户采购使用。
```

## 3. 选择垂直市场的标准

| 标准 | 说明 |
| --- | --- |
| 需求强度 | 是否存在明显就业、转岗、晋升、接单或合规需求 |
| 可自动评分 | 题目、任务、项目是否能自动评分 |
| 可远程交付 | 是否适合线上学习、考试和证书签发 |
| 非强监管风险 | 是否避免国家资格、医疗诊断、法律执业等高风险边界 |
| Verifier 清晰 | 是否有明确用人单位、客户、学校或项目方会验证 |
| 用户愿付费 | 学习者或组织是否愿意为证书付费 |
| 创始人优势 | 我们是否有领域经验、内容能力或案例基础 |
| Crypto Proof 价值 | 链上证明是否真的提升可信度和可携带性 |

## 5. 推荐第一垂直：AI-enhanced Software Development

第一版最推荐：

```text
AI-enhanced Software Development Certificate
```

中文：

```text
AI 增强软件开发能力证书
```

原因：

```text
创始人懂软件开发。
国际市场软件开发岗位对 AI 编程、代码审查、测试、验证、DevOps 的需求明显。
考试和项目任务可以自动评分。
代码、测试、PR、issue、review、CI 结果天然适合 Evidence Package。
Verifier 明确：技术团队、招聘方、外包客户、开源项目方。
Crypto Proof 有价值：候选人可以把可验证项目能力带给雇主或客户。
```

## 6. 第一垂直不是“AI 编程课”

不能做成普通：

```text
教你用 ChatGPT 写代码
教你用 Copilot 补全代码
教你快速学 Python
```

正确定位是：

```text
证明一个人能在 AI / Agent 时代完成可验证的软件交付任务。
```

能力重点：

```text
需求理解
任务拆解
AI 辅助编码
代码审查
测试生成
Bug 定位
安全意识
文档生成
PR 说明
CI / 质量检查
Evidence Package
```

## 7. AI-enhanced Software Development：能力模块

| 模块 | 名称 | 说明 |
| --- | --- | --- |
| SD1 | Requirement to Task | 把需求转成 issue、user story、acceptance criteria |
| SD2 | AI-assisted Implementation | 使用 AI 辅助实现小功能，但能控制质量 |
| SD3 | Code Understanding | 阅读现有代码，理解模块、接口、数据流 |
| SD4 | Testing with AI | 用 AI 生成单元测试、边界用例和测试数据 |
| SD5 | Debugging with AI | 利用日志、错误信息、测试失败定位问题 |
| SD6 | Code Review & Refactoring | 审查 AI 生成代码，发现坏味道和风险 |
| SD7 | Secure Coding Awareness | 识别注入、权限、泄露、依赖风险 |
| SD8 | DevOps / CI Awareness | 理解基本构建、测试、lint、CI 失败原因 |
| SD9 | Documentation & PR Communication | 写 README、变更说明、PR 描述、用户说明 |
| SD10 | Agentic Software Workflow | 设计“需求->代码->测试->审查->提交”的 Agent 工作流 |
| SD11 | Evidence & Proof | 把代码、测试、PR、评分结果打包成可验证证据 |

## 8. 第一版项目任务建议

项目任务：

```text
AI-assisted Bug Fix & Feature Delivery
```

给学习者一个小型代码仓库和任务说明。

要求完成：

```text
1. 阅读需求并写出任务拆解。
2. 使用 AI 辅助理解代码。
3. 修复一个 bug 或实现一个小功能。
4. 添加或修改测试。
5. 运行测试并解释结果。
6. 写出 PR summary。
7. 标记 AI 使用过程和风险点。
8. 生成 Evidence Package。
```

自动评分依据：

```text
测试是否通过
代码是否符合要求
是否覆盖边界用例
是否有明显安全风险
PR 描述是否清楚
证据链是否完整
```

## 9. 第一版题型建议

| 题型 | 用途 |
| --- | --- |
| 单选 / 多选 | 基础概念、代码安全、AI 使用边界 |
| 代码阅读题 | 判断函数行为、接口含义、错误原因 |
| Bug 定位题 | 根据日志、测试失败、错误堆栈定位问题 |
| 测试用例题 | 选择合适边界用例和测试策略 |
| Code Review 题 | 找出 AI 生成代码中的问题 |
| Prompt 设计题 | 给 AI 编写实现、测试、debug、review 任务上下文 |
| 项目任务 | 完成一个真实小交付 |

## 10. 为什么其他方向暂不做第一版

### 10.1 Healthcare / Caregiving / Nutrition

这个方向市场很大，但问题是：

```text
涉及健康建议、护理标准、营养建议和潜在医疗边界。
各国监管差异大。
需要领域专家和合规审查。
很多证书已有成熟体系。
第一版容易踩医疗或虚假认证风险。
```

可以作为未来方向，但不适合作为一人公司第一版 MVP。

### 10.2 Food Safety / Compliance

这个方向也是真实市场，因为食品安全、餐饮、供应链里证书和审计很多。

但问题是：

```text
需要熟悉 HACCP、ISO 22000、GFSI、当地法规。
题库可以做，但证书边界必须非常谨慎。
Verifier 主要是企业和供应链，不一定适合 C 端冷启动。
```

可以作为第二阶段 B2B 方向。

### 10.3 Generic AI Agent Operator

这个方向有前沿感，但问题是：

```text
太抽象。
岗位定义不稳定。
题库难和具体招聘场景绑定。
Verifier 不知道该怎么判断证书价值。
```

应该作为每个垂直证书里的能力层，而不是单独第一证书。

## 11. 推荐产品路线

| 阶段 | 方向 | 说明 |
| --- | --- | --- |
| v6.3 | AI-enhanced Software Development | 第一垂直，最贴合创始人能力和自动评分 |
| v6.4 | AI Data / BI Assistant | 第二垂直，适合自动评分和企业需求 |
| v6.5 | AI Product / Business Analyst | 适合企业培训和咨询式交付 |
| v6.6 | AI Cybersecurity Awareness / AppSec | 高需求，但要控制安全边界 |
| v7.x | Food Safety / Caregiving / Youth AI Literacy | 大市场，但需要合规与领域专家 |

## 12. 与通用 AI 能力的关系

通用 AI 能力不消失，但要嵌入垂直领域。

```text
Prompt engineering -> 软件需求、代码、测试、review prompt
Agent workflow -> 软件开发 workflow
Tool use -> GitHub、CI、log、test runner、issue tracker
Verification -> 测试、lint、安全检查、代码审查
Proof -> PR、commit、test result、Evidence Package
```

这才是可销售、可评测、可验证的能力证书。

## 13. 下一步问题

需要继续确认：

```text
第一张证书是否改成 AI-enhanced Software Development Certificate？
第一版代码语言选 JavaScript/TypeScript、Python，还是 Java？
项目任务用前端小功能、后端 API、小脚本、还是 bug fix？
证书面向初级开发者、转型者，还是已有经验的开发者？
```

建议默认：

```text
证书：AI-enhanced Software Development Certificate
语言：JavaScript/TypeScript + Python 二选一，先选 TypeScript 更贴近 Web 产品
任务：小型 bug fix + test + PR summary
对象：初级到中级开发者、转型者、自由职业接单者
```
