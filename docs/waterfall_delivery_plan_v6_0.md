## 0. 重构目标

本项目从“页面驱动的原型堆叠”，重构为“AI 时代个人能力提升与再教育平台”。

正确交付顺序：

```text
战略分析
-> 目标用户与痛点把握
-> 领域诊断桥：AS-IS / TO-BE / Gap
-> TOGAF 分层功能架构
-> 三层数据架构
-> 原型设计
-> 技术架构
```

关键纠偏：

```text
目标客户不是咨询公司。
咨询只是我们内部使用的方法和交付手段。
目标客户是所有在 AI 时代想提升自己能力的成年人。

痛点不是功能。
痛点只是输入信号。
功能必须来自能力提升领域的 TO-BE 目标能力。
数据必须来自 TO-BE 能力、学习过程、任务训练、作品证据、评价和成长报告。
```

## 1. 战略分析

### 1.1 战略定位

```text
AI 时代个人能力提升与再教育平台
```

客户购买的不是一门孤立课程，也不是一个 AI 工具演示，而是一套帮助学习者完成能力诊断、训练路径、任务练习、作品沉淀、能力证明和成长报告的系统。

系统要帮助学习者回答：

```text
我在 AI 时代应该提升什么能力？
我当前能力和目标能力之间差在哪里？
我应该按什么路径练习？
我的练习结果如何被评价？
我如何把学习结果变成作品、履历、报告和能力证明？
```

### 1.2 目标客户

目标客户是：

```text
所有在 AI 时代想提升自己能力的成年人。
```

这个定义不以企业大小为边界，也不以是否在企业内部为边界。企业可以是采购渠道，培训机构和社群也可以是渠道，但最终服务对象是想提升自身能力的人。

| 目标客户类型 | 核心诉求 | 平台应提供的价值 |
| --- | --- | --- |
| 普通职场人 | 担心 AI 影响岗位，希望提升效率和竞争力 | AI 时代能力诊断、学习路径、任务训练、能力证明 |
| 转型 / 跳槽 / 再就业人群 | 想进入新岗位，但缺少清晰路径和作品证明 | 能力差距分析、训练任务、作品集、Proof File |
| 自由职业者 / 个体服务者 | 希望用 AI 提升交付能力、获客能力和服务质量 | AI 辅助交付训练、客户沟通训练、案例沉淀 |
| 管理者 / 小老板 | 希望理解 AI、使用 AI、管理 AI 工作流 | AI 管理能力训练、业务场景练习、决策表达训练 |
| 企业员工群体 | 企业希望员工整体提升 AI 能力 | 团队训练、任务分配、学习进度、能力报告 |
| 创业者 / 斜杠青年 | 希望用 AI 验证想法、做内容、做产品、做服务 | AI 创业任务、方案生成、原型训练、商业表达训练 |
| 终身学习者 | 希望持续更新能力，不被时代淘汰 | 个性化学习路径、阶段评估、成长记录 |

### 1.3 目标客户、渠道和方法的边界

```text
目标客户：AI 时代想提升能力的个人。
组织采购渠道：企业、培训机构、社群、继续教育部门、人力资源部门。
内部交付方法：咨询方法、诊断方法、AS-IS / TO-BE 分析、TOGAF 架构方法。
```

因此：

```text
咨询不是目标客户。
企业不是唯一目标客户。
企业大小不是本项目的核心边界。
能力提升人群才是核心边界。
```

### 1.4 商业边界

不能承诺：

```text
官方证书
保证就业
保证薪资
保证收入
保证创业成功
受监管职业资格
```

可以销售：

```text
AI 时代能力诊断
个性化学习路径
任务化训练
AI 工作流练习
作品集沉淀
Proof File 能力证明
学习报告 / Readiness 报告
团队能力提升包
```

## 2. 目标用户与痛点把握

痛点把握不是功能清单。痛点只是发现问题的输入，用来判断能力提升领域为什么必须变化。

### 2.1 用户痛点矩阵

| 用户对象 | 痛点信号 | 说明该领域缺少什么 |
| --- | --- | --- |
| 普通职场人 | 感觉 AI 很重要，但不知道自己该学什么 | 缺少面向个人的 AI 时代能力诊断 |
| 转型 / 再就业人群 | 学了很多内容，但不能证明自己能胜任新岗位 | 缺少任务化训练、作品集和能力证明 |
| 自由职业者 | 会一些 AI 工具，但难变成稳定交付能力 | 缺少真实业务场景练习和交付证据 |
| 管理者 / 小老板 | 想用 AI 提升团队，但不知道如何设计工作流 | 缺少 AI 工作流理解、场景训练和管理能力提升 |
| 企业员工 | 培训完成不等于能力提升，培训结果难评价 | 缺少任务、评分、评审、报告和团队 Readiness 指标 |
| 创业者 / 斜杠青年 | 想法很多，但缺少用 AI 快速验证和表达的训练路径 | 缺少从想法到方案、内容、原型、案例的训练闭环 |
| 终身学习者 | 知识更新太快，缺少持续成长记录 | 缺少长期能力档案、学习路径和阶段评价 |

### 2.2 痛点到架构的转换规则

痛点不能直接变成页面或功能，必须经过中间桥接层。

```text
痛点信号
-> 根因分析
-> AS-IS 现状
-> TO-BE 目标
-> 差距 Gap
-> 目标功能
-> 目标数据
-> 原型需求
```

## 3. 领域诊断桥：AS-IS / TO-BE / Gap

这是痛点和架构之间的桥。没有这一层，系统会变成“课程页面集合”或“痛点页面集合”，而不是一个真正可扩展的能力提升平台。

### 3.1 桥接模型

| 步骤 | 要回答的问题 | 输出物 |
| --- | --- | --- |
| 痛点信号 | 学习者现在卡在哪里？ | 痛点描述 |
| 根因分析 | 为什么学不会、用不好、证明不了？ | 能力弱点和学习障碍 |
| AS-IS | 当前能力提升如何发生？ | 当前学习 / 练习 / 评价 / 证明现状 |
| TO-BE | AI 时代能力提升应该如何发生？ | 目标学习与成长模式 |
| Gap | AS-IS 到 TO-BE 中间缺什么？ | 能力差距、路径差距、任务差距、证据差距、评价差距 |
| 架构设计 | 平台要建设什么？ | 功能架构和数据架构 |

### 3.2 领域级 AS-IS / TO-BE 总览

| 领域方面 | AS-IS 当前状态 | TO-BE 目标状态 | 需要弥补的 Gap |
| --- | --- | --- | --- |
| 学习目标 | 学习者知道 AI 重要，但目标模糊 | 能明确自己要提升的岗位能力、AI 能力和交付能力 | 能力诊断与目标建模 |
| 学习路径 | 靠课程目录、短视频、经验碎片学习 | 根据目标能力生成阶段化学习路径和任务路径 | 个性化路径设计 |
| 练习方式 | 看课多，真实任务少，练完不知道水平如何 | 每个能力点都有任务、场景、评分规则和反馈 | 任务化训练模型 |
| AI 使用 | 零散学习工具和提示词 | 围绕真实工作场景练习 AI 工作流 | 场景化 AI 工作流训练 |
| 评价方式 | 评价停留在是否完成课程或答题分数 | 评价覆盖任务完成度、输出质量、AI 使用过程和改进能力 | 多维评价模型 |
| 作品沉淀 | 学习成果分散，难用于求职、接单或晋升 | 学习成果沉淀为作品、案例、Proof File 和能力档案 | 作品与证据链 |
| 能力证明 | 难证明“我真的会用 AI 做事” | 平台能输出可解释的能力证明和 Readiness 报告 | Proof 与报告体系 |
| 团队训练 | 企业培训难判断成员是否真正掌握 | 企业可看到团队任务完成、能力分布和提升建议 | 团队 Readiness 视图 |

### 3.3 场景级 AS-IS / TO-BE 示例

| 场景 | AS-IS | TO-BE | 需要的目标能力 |
| --- | --- | --- | --- |
| 职场效率提升 | 学习者知道 AI 工具，但不知道如何嵌入日常工作 | 围绕邮件、汇报、分析、会议、文档等任务练习 AI 工作流 | 工作场景任务库、AI 使用评价 |
| 转型求职 | 学习内容多，但缺少岗位相关作品 | 按目标岗位完成项目任务、案例输出和 Proof File | 岗位能力模型、作品集与证明 |
| 自由职业交付 | 会工具，但交付过程不稳定 | 练习需求沟通、方案生成、交付物制作和客户复盘 | 交付任务链、客户场景训练 |
| 管理者 AI 升级 | 理解 AI 概念，但不会设计团队工作流 | 练习场景拆解、任务分配、风险控制和结果评审 | 管理者 AI 工作流训练 |
| 企业团队培训 | 企业组织培训，但结果难量化 | 团队成员完成任务、接受评审，生成团队 Readiness 报告 | 团队任务、评审、报告体系 |

## 6. 功能与数据追溯矩阵

未来每个页面、报表、接口和实现任务，都必须通过以下追溯检查。

| 追溯层级 | 必须满足的映射关系 |
| --- | --- |
| 用户痛点 | 痛点只能映射到根因和 AS-IS / TO-BE 分析，不能直接变成功能 |
| AS-IS / TO-BE | 每个目标功能都必须能说明来自哪个 AS-IS 弱点和哪个 TO-BE 目标 |
| 一级 | 一级功能必须映射到一个一级数据域 |
| 二级 | 二级功能必须映射到一个或多个二级数据主题 |
| 三级 | 三级功能必须映射到具体三级数据实体和字段 |
| 学习证据 | 任意报告字段必须能追溯到任务、提交、评分、评审或 Proof File |
| 对外展示 | 任意对外可见字段必须有 visibility rule |
| 审计 | 任意评审、导出、Proof 动作必须产生 AuditEvent |

| TOGAF 层 | 本项目中的内容 |

## 10. 验收清单

本次瀑布式重构文档可验收的标准：

```text
战略口径清楚：不是咨询公司系统，不是单纯课程平台，而是 AI 时代个人能力提升与再教育平台。
目标客户清楚：所有在 AI 时代想提升自己能力的成年人。

痛点边界清楚：痛点是输入，不是功能。
桥接层清楚：痛点 -> 根因 -> AS-IS -> TO-BE -> Gap -> 架构。
AS-IS / TO-BE 清楚：按能力提升领域列出现状和目标状态。
功能分层清楚：一级功能、二级功能、三级功能来自 TO-BE 目标能力。
数据分层清楚：一级数据域、二级数据主题、三级数据实体支撑学习路径、任务训练、证据、Proof 和报告。
TOGAF 清楚：业务、应用、数据、技术层可追溯。
数据链路清楚：Proof File 和 Report 能追溯到任务、提交、评分、评审和证据。
原型边界清楚：原型设计先定义页面目的、输入、输出、动作、评审和可见字段。
技术边界清楚：Streamlit MVP 和未来正式生产架构分离。
```
