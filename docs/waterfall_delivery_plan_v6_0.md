## 0. 重构目标

本项目从“页面驱动的原型堆叠”，重构为“AI 时代个人能力提升与再教育平台”。

正确交付顺序：

```text
战略分析
-> 目标用户与痛点把握
-> 领域诊断桥：AS-IS / TO-BE / Gap
-> TOGAF 分层功能架构
-> 三层数据架构
-> 原型设计
-> 技术架构
```

关键纠偏：

```text
目标客户不是咨询公司。
咨询只是我们内部使用的方法和交付手段。
核心目标客户是所有在 AI 时代想提升自己能力的人。
主线是成年人能力提升；支线可以扩展到未成年人 AI 素养与创造力成长。

痛点不是功能。
痛点只是输入信号。
功能必须来自能力提升领域的 TO-BE 目标能力。
数据必须来自 TO-BE 能力、学习过程、任务训练、作品证据、评价、Proof 和成长报告。
```

## 1. 战略分析

### 1.1 战略定位

```text
AI 时代个人能力提升、素养成长与可信证明平台
```

客户购买的不是一门孤立课程，也不是一个 AI 工具演示，而是一套帮助学习者完成能力诊断、训练路径、任务练习、作品沉淀、能力评测、Proof 证明和成长报告的系统。

系统要帮助学习者回答：

```text
我在 AI 时代应该提升什么能力？
我当前能力和目标能力之间差在哪里？
我应该按什么路径练习？
我的练习结果如何被评价？
我如何把学习结果变成作品、履历、报告和能力证明？
我的能力证明如何可信、可验证、可长期保存？
```

### 1.2 目标客户

目标客户是：

```text
所有在 AI 时代想提升自己能力的人。
```

市场主线仍然是成年人，因为成人再教育、职业转型、自由职业、企业员工培训和管理者提升更容易商业化。未成年人可以作为更大的长期支线，但必须定位为“AI 素养、创造力、项目式能力成长”，不能做学科补课、应试提分、作业代做或变相校外学科培训。

| 目标客户类型 | 核心诉求 | 平台应提供的价值 |
| --- | --- | --- |
| 普通职场人 | 担心 AI 影响岗位，希望提升效率和竞争力 | AI 时代能力诊断、学习路径、任务训练、能力证明 |
| 转型 / 跳槽 / 再就业人群 | 想进入新岗位，但缺少清晰路径和作品证明 | 能力差距分析、训练任务、作品集、Proof File |
| 自由职业者 / 个体服务者 | 希望用 AI 提升交付能力、获客能力和服务质量 | AI 辅助交付训练、客户沟通训练、案例沉淀 |
| 管理者 / 小老板 | 希望理解 AI、使用 AI、管理 AI 工作流 | AI 管理能力训练、业务场景练习、决策表达训练 |
| 企业员工群体 | 企业希望员工整体提升 AI 能力 | 团队训练、任务分配、学习进度、能力报告 |
| 创业者 / 斜杠青年 | 希望用 AI 验证想法、做内容、做产品、做服务 | AI 创业任务、方案生成、原型训练、商业表达训练 |
| 终身学习者 | 希望持续更新能力，不被时代淘汰 | 个性化学习路径、阶段评估、成长记录 |
| 未成年人 / 青少年 | 希望在 AI 时代培养创造力、表达力、项目能力和数字素养 | AI 素养任务、项目式学习、成长档案、监护人可控证明 |

### 1.3 未成年人业务边界

未成年人可以加入，但必须独立设置合规边界。

允许方向：

```text
AI 素养
创造力训练
表达与写作素养
项目式学习
数字素养
信息检索与判断
逻辑思维
编程兴趣与计算思维
作品集与成长档案
监护人可见的能力评测
```

禁止方向：

```text
义务教育阶段学科类补课
应试提分承诺
刷题提分服务
作业代写 / 拍照搜题 / 变相答案服务
校内考试排名包装
中高考升学承诺
制造额外学习负担的高压训练
未经监护人同意采集或公开儿童个人信息
```

未成年人产品表达应使用：

```text
AI 素养成长
创造力项目
数字能力成长档案
项目式学习成果
监护人可控成长证明
```

不要使用：

```text
补课
提分
押题
升学保证
名校保证
应试冲刺
```

### 1.4 目标客户、渠道和方法的边界

```text
目标客户：AI 时代想提升能力的个人，包括成年人和合规边界内的未成年人。
组织采购渠道：企业、培训机构、社群、继续教育部门、人力资源部门、家长社群、国际学校 / 海外教育社区。
内部交付方法：咨询方法、诊断方法、AS-IS / TO-BE 分析、TOGAF 架构方法。
```

因此：

```text
咨询不是目标客户。
企业不是唯一目标客户。
企业大小不是本项目的核心边界。
成年人能力提升是近期主线。
未成年人 AI 素养成长是长期大市场支线。
能力评测和可信证明是成年人和未成年人都需要的共同核心。
```

### 1.5 商业边界

不能承诺：

```text
官方证书
保证就业
保证薪资
保证收入
保证创业成功
保证升学
保证提分
受监管职业资格
```

可以销售：

```text
AI 时代能力诊断
个性化学习路径
任务化训练
AI 工作流练习
作品集沉淀
Proof File 能力证明
学习报告 / Readiness 报告
未成年人 AI 素养成长档案
企业团队能力提升包
```

## 2. 目标用户与痛点把握

痛点把握不是功能清单。痛点只是发现问题的输入，用来判断能力提升领域为什么必须变化。

### 2.1 用户痛点矩阵

| 用户对象 | 痛点信号 | 说明该领域缺少什么 |
| --- | --- | --- |
| 普通职场人 | 感觉 AI 很重要，但不知道自己该学什么 | 缺少面向个人的 AI 时代能力诊断 |
| 转型 / 再就业人群 | 学了很多内容，但不能证明自己能胜任新岗位 | 缺少任务化训练、作品集和能力证明 |
| 自由职业者 | 会一些 AI 工具，但难变成稳定交付能力 | 缺少真实业务场景练习和交付证据 |
| 管理者 / 小老板 | 想用 AI 提升团队，但不知道如何设计工作流 | 缺少 AI 工作流理解、场景训练和管理能力提升 |
| 企业员工 | 培训完成不等于能力提升，培训结果难评价 | 缺少任务、评分、评审、报告和团队 Readiness 指标 |
| 创业者 / 斜杠青年 | 想法很多，但缺少用 AI 快速验证和表达的训练路径 | 缺少从想法到方案、内容、原型、案例的训练闭环 |
| 终身学习者 | 知识更新太快，缺少持续成长记录 | 缺少长期能力档案、学习路径和阶段评价 |
| 未成年人 / 青少年 | AI 已经进入学习和生活，但缺少安全、健康、非应试的能力成长路径 | 缺少 AI 素养、项目式学习、成长证明和监护人控制机制 |

### 2.2 痛点到架构的转换规则

痛点不能直接变成页面或功能，必须经过中间桥接层。

```text
痛点信号
-> 根因分析
-> AS-IS 现状
-> TO-BE 目标
-> 差距 Gap
-> 目标功能
-> 目标数据
-> 原型需求
```

## 3. 领域诊断桥：AS-IS / TO-BE / Gap

这是痛点和架构之间的桥。没有这一层，系统会变成“课程页面集合”或“痛点页面集合”，而不是一个真正可扩展的能力提升平台。

### 3.1 桥接模型

| 步骤 | 要回答的问题 | 输出物 |
| --- | --- | --- |
| 痛点信号 | 学习者现在卡在哪里？ | 痛点描述 |
| 根因分析 | 为什么学不会、用不好、证明不了？ | 能力弱点和学习障碍 |
| AS-IS | 当前能力提升如何发生？ | 当前学习 / 练习 / 评价 / 证明现状 |
| TO-BE | AI 时代能力提升应该如何发生？ | 目标学习与成长模式 |
| Gap | AS-IS 到 TO-BE 中间缺什么？ | 能力差距、路径差距、任务差距、证据差距、评价差距 |
| 架构设计 | 平台要建设什么？ | 功能架构、数据架构和可信证明架构 |

### 3.2 领域级 AS-IS / TO-BE 总览

| 领域方面 | AS-IS 当前状态 | TO-BE 目标状态 | 需要弥补的 Gap |
| --- | --- | --- | --- |
| 学习目标 | 学习者知道 AI 重要，但目标模糊 | 能明确自己要提升的岗位能力、AI 能力、创造力和交付能力 | 能力诊断与目标建模 |
| 学习路径 | 靠课程目录、短视频、经验碎片学习 | 根据目标能力生成阶段化学习路径和任务路径 | 个性化路径设计 |
| 练习方式 | 看课多，真实任务少，练完不知道水平如何 | 每个能力点都有任务、场景、评分规则和反馈 | 任务化训练模型 |
| AI 使用 | 零散学习工具和提示词 | 围绕真实工作或项目场景练习 AI 工作流 | 场景化 AI 工作流训练 |
| 评价方式 | 评价停留在是否完成课程或答题分数 | 评价覆盖任务完成度、输出质量、AI 使用过程和改进能力 | 多维评价模型 |
| 作品沉淀 | 学习成果分散，难用于求职、接单、展示或成长记录 | 学习成果沉淀为作品、案例、Proof File 和能力档案 | 作品与证据链 |
| 能力证明 | 难证明“我真的会用 AI 做事” | 平台能输出可解释、可验证、可长期保存的能力证明和 Readiness 报告 | Proof 与可信验证体系 |
| 未成年人学习 | 容易滑向补课、刷题或额外负担 | 定位为 AI 素养、创造力、项目式成长和监护人可控档案 | 合规边界和儿童安全设计 |
| 团队训练 | 企业培训难判断成员是否真正掌握 | 企业可看到团队任务完成、能力分布和提升建议 | 团队 Readiness 视图 |

## 6. 可信证明与区块链路线

能力评测和证明是成年人和未成年人都需要的共同核心，但上链策略必须保守。

### 6.1 证明原则

```text
原始学习内容不上链。
个人隐私不上链。
未成年人身份信息不上链。
链上只放哈希、时间戳、签发方、状态和撤销信息。
Proof File 内容由用户或监护人控制可见范围。
```

### 6.2 海外优先路线：Frontend + Blockchain Proof Backend

海外可以优先探索 Web3-first 架构：

```text
前端应用
-> 钱包 / DID 身份
-> 本地或用户控制的加密资料存储
-> 链上 Proof Registry
-> 可验证能力证明
```

这里的“不要数据库”应理解为：

```text
不建设中心化业务数据库作为可信证明的唯一来源。
```

但仍然需要某种形式的用户侧或去中心化存储保存学习内容、作品文件和报告原文。链上只保存证明摘要，不保存个人学习隐私。

### 6.3 国内路线：联盟链或暂不进入

国内如使用区块链，应优先考虑：

```text
合规联盟链 / 许可链
实名与备案要求
内容安全管理
日志留存
不发行 Token
不做虚拟币叙事
不把未成年人隐私写入链上
```

如果国内合规路线不清晰，则可以先选择：

```text
海外市场优先
国内只做非链版本或联盟链试点
暂不面向国内未成年人市场
```

### 6.4 推荐阶段策略

| 阶段 | 市场 | 技术路线 | 说明 |
| --- | --- | --- | --- |
| Phase 1 | 海外成年人 | 前端 + 钱包 + 链上 Proof Registry | 最适合验证“能力证明”差异化 |
| Phase 2 | 海外青少年 | 增加监护人控制和儿童隐私保护 | 只做 AI 素养与项目成长，不做学科补课 |
| Phase 3 | 国内成年人 | 可选普通 Web 或联盟链 | 避免公链和 Token 叙事 |
| Phase 4 | 国内未成年人 | 只有合规确认后再进入 | 必须避开双减红线 |

## 11. 验收清单

本次瀑布式重构文档可验收的标准：

```text
战略口径清楚：不是咨询公司系统，不是单纯课程平台，而是 AI 时代能力提升、素养成长与可信证明平台。
目标客户清楚：主线是成年人，支线可扩展到未成年人 AI 素养成长。
未成年人边界清楚：不做学科补课、不做应试提分、不做作业答案服务、不增加高压负担。
渠道边界清楚：企业、培训机构、社群、家长社群可以是渠道或组织采购方，但不是唯一目标客户定义。
咨询边界清楚：咨询只是内部方法和交付手段，不是目标客户。
痛点边界清楚：痛点是输入，不是功能。
桥接层清楚：痛点 -> 根因 -> AS-IS -> TO-BE -> Gap -> 架构。
功能分层清楚：一级功能、二级功能、三级功能来自 TO-BE 目标能力。
数据分层清楚：一级数据域、二级数据主题、三级数据实体支撑学习路径、任务训练、证据、Proof、链上证明和报告。
可信证明清楚：链上只放哈希、状态和验证信息，不放个人隐私和未成年人敏感信息。
```
